Every table is append-only. A correction, a recomputed bin, or a reloaded reference row is a new row, and readers take the newest row per key. So a row count measures writes, and a key count measures things. Largest gaps: {% for row in widest %}{{ row.table }} has {{ row.scan_rows|u_int }} rows for {{ row['keys']|u_int }} keys{{ ', ' if not loop.last else '.' }}{% else %}no table has more rows than keys.{% endfor %}

gold.* tables recompute recent bins each cycle and append a row when a count changes, so one 5-minute bin can hold several rows. Rows come from the catalog, which knows them without opening a file. Keys need a scan, so they run in a child process and can trail the catalog by up to 2 minutes.
