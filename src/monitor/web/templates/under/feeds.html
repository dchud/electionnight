{% call u.caveat("How to read the saving") %}

A 304 sends no body, so nothing measures what it saved. The estimate is the mean size of that feed's 200 responses, counted for the {{ c.not_modified_sized|u_int }} of {{ c.not_modified|u_int }} 304s whose feed has a recorded size. Sizes exist only since capture started. Of {{ c.detailed_responses|u_int }} recorded 200 responses, {{ c.unchanged_bodies|u_int }} had a body identical to the last one, which means the server ignored the validators.

Entries served against items kept, by tier

{% call u.caveat("Yield credits the first feed only") %}

An item is new once. It counts for whichever feed served it first, which favors the fastest poller, so a low yield can mean a feed was beaten to items it also carries. Sightings show what each feed carried since capture started. Most kept items are first-fetch backlog, so all-time yield overstates a feed's rate.
