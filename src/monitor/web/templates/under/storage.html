DuckLake keeps table definitions, file lists, and small inserts in a SQLite catalog, and larger data in Parquet files. Each commit is a numbered snapshot. Row counts on this page count rows, not records: Inventory shows the difference.

What a merge and a cleanup do

  • Flush moves inlined rows from the catalog into Parquet. Merge rewrites small adjacent files as one file. Neither changes what any query returns, at any snapshot.
  • A merged file keeps each row's snapshot range, in _ducklake_internal_snapshot_id. So AT (VERSION => n) stays exact after the replaced files are gone. This was checked on a scratch lake.
  • Cleanup deletes replaced files from disk once they are 2 hours old, which leaves any query still reading them time to finish.
